# Database

PostgreSQL 17 is the single source of truth ([ADR-0002](../decisions/0002-postgresql-source-of-truth.md)).
This document holds the conventions and the high-level model. Tables are created by the phase
that needs them. Phase 0 creates only the Laravel framework tables and the append-only guard
function.

## Conventions

| Topic | Rule |
|---|---|
| Money | `bigint` whole rupiah (Rp2.000 → `2000`). Never `float`, `double`, `real` or `numeric` with decimals. Column names end in `_amount`. |
| Time | `timestamptz`, stored and compared in UTC. Displayed in `Asia/Jakarta` (WIB) by the UI. Device and server times are separate columns (`*_at_device`, `*_at_server`). |
| Identifiers | `bigint` identity PK internally; client-generated `uuid` (`*_uuid`, unique) for anything created on a device; human-readable `*_number` generated by the server. |
| Status | `varchar` + `CHECK (status IN (...))`, mirrored by a PHP enum with allowed transitions. |
| Integrity | Foreign keys everywhere; unique and partial unique indexes for business invariants; `CHECK` for value ranges (for example `amount > 0`). |
| Deletes | No hard delete of financial data. No `ON DELETE CASCADE` into financial tables. |
| Append-only | Protected with `AppendOnlyTable::protect()` ([ADR-0007](../decisions/0007-financial-ledger-immutability.md)). |
| Migrations | Reversible `down()` where possible; one concern per migration; never edit a migration that has run in a shared environment. |
| Indexes | Add them for real query paths (master doc §37). Do not index speculatively. |
| Testing | Constraints, triggers and locking are tested against real PostgreSQL (`pati_parking_test`). |

## Phase 2 schema (Master Data)

Rules and rationale: [ADR-0010](../decisions/0010-master-data-rules.md). Requires the `btree_gist` extension.

| Table | Key constraints |
|---|---|
| `parking_locations` | unique upper-case `location_code` (CHECK format); CHECK lat/long ranges, radius 5–1000 m, type `ON_STREET/OFF_STREET/EVENT`, status, capacities ≥ 0 |
| `parking_attendants` | `attendant_code` from sequence `parking_attendant_code_seq` (owned by the column), CHECK `^JP-[0-9]{6,}$`; unique `user_id` (one login each, FK restrict); unique 16-digit NIK (CHECK); CHECK phone, status, validity dates |
| `devices` | unique `device_uuid`; FK attendant; CHECK status, approval ⇒ `approved_at`, REVOKED/LOST ⇒ `deactivated_at`; **partial unique `(attendant_id) WHERE status = 'ACTIVE'`** |
| `assignments` | CHECK period, status `ACTIVE/CANCELLED`; **exclusion: no overlapping ACTIVE `daterange` per attendant** |
| `tariffs` | CHECK amount > 0, period, status, approval fields; **CHECK `approved_by <> created_by`**; **exclusion: approved tariffs of one scope `(vehicle_type, location_type, COALESCE(location_id,0))` never overlap (`tstzrange`)**; trigger `tariffs_guard()`: approved rows frozen except closing an open validity, rejected rows final, no DELETE/TRUNCATE |

Note: `migrate:fresh` drops tables only. Standalone functions use `CREATE OR REPLACE`, and
sequences are `OWNED BY` a column, so repeated fresh migrations stay clean.

## Phase 3 schema (Shift & settings)

| Table | Key constraints |
|---|---|
| `system_settings` | PK `key`; CHECK value is a JSON scalar. Only overridden values are stored; defaults live in code |
| `shifts` | unique `shift_uuid`; FKs attendant, location, device, assignment (nullable: offline mismatch); CHECK status `OPEN/CLOSED/FORCED_CLOSED`, geofence values, closed ⇒ `ended_at_server`, forced ⇒ closer + reason, end ≥ start, flags is a JSON array; **partial unique `(attendant_id) WHERE status = 'OPEN'`**; payload hashes for idempotent start/end |

| Table | Key constraints |
|---|---|
| `parking_transactions` | unique `transaction_uuid`, `transaction_number` (sequence, `TRX-YYMMDD-########`), `(device_id, sync_sequence)`; FKs shift/attendant/location/device/tariff; CHECK vehicle, method, status, amounts > 0, `difference = expected − charged`, CASH only COMPLETED/VOID_REQUESTED/VOIDED, plate format, flags array; **trigger `parking_transactions_guard()`**: frozen columns, §47 transitions only, no DELETE/TRUNCATE |

## Phase 6 schema (QRIS payments)

| Table | Key constraints |
|---|---|
| `payments` | unique `payment_uuid`, `transaction_id` (one payment per QRIS transaction), `provider_order_id` (= payment_uuid), `(provider, provider_reference)`; CHECK provider, method QRIS, amount > 0, status, `PAID ⇔ paid_at`, PENDING needs reference + expiry; **trigger `payments_guard()`**: identity/amount frozen, provider data set once, forward-only status (PAID final, late PAID allowed), no DELETE/TRUNCATE |
| `payment_provider_events` | **append-only**; every verified provider answer (CHARGE, STATUS_CHECK, CANCEL, WEBHOOK) with outcome and status before/after; unique `event_key` (webhook dedupe); payload without signature |
| `payment_adjustments` | **append-only**; `MANUAL_REFUND` only; amount > 0; reason ≥ 5 chars; **trigger**: only for PAID payments, total ≤ payment amount |
| `parking_transactions` (added) | CHECK `parking_transactions_qris_check`: QRIS ⇒ online and difference 0 |

## Phase 7 schema (Cash settlement)

|---|---|

## High-level model (target)

```text
users ─1:1─ parking_attendants ─1:N─ devices (PENDING_APPROVAL | ACTIVE | REVOKED | LOST)
                  │   └─1:N─ assignments ─N:1─ parking_locations
                  └─1:N─ shifts (shift_uuid) ─1:N─ parking_transactions (transaction_uuid)
                                                        │         └─1:N─ payments ─1:N─ payment_provider_events
tariffs (versioned) ◄── tariff_id + charged_tariff_amount / server_expected_tariff_amount
                                                        │
attendant_cash_balances (derived) ◄── cash_ledger_entries (append-only, source of truth)
                                                        └─► transaction_id | settlement_id

payment_adjustments (MANUAL_REFUND, …) ──► payments
cash_settlements, void_requests, anomaly_flags, reconciliations (+ items),
audit_logs (append-only), system_settings, mobile_refresh_tokens
```

### Key invariants and the constraints that will enforce them

| Invariant (master doc §46 + approvals) | Enforcement |
|---|---|
| One open shift per attendant | partial unique index `shifts(attendant_id) WHERE status = 'OPEN'` |
| One active device per attendant | partial unique index `devices(attendant_id) WHERE status = 'ACTIVE'`; `device_uuid` unique |
| Pending/revoked devices cannot operate | checked in Shift/ParkingTransaction Actions (`DEVICE_NOT_ALLOWED`) |
| A transaction UUID exists once | unique `parking_transactions.transaction_uuid`; unique `(device_id, sync_sequence)`; unique `transaction_number` |
| A shift UUID exists once | unique `shifts.shift_uuid` |
| Paid payment never goes back | trigger `payments_guard()` + `PaymentStateMachine` (payment row locked) |
| One payment per QRIS transaction | unique `payments.transaction_id`; a retry after expiry is a new transaction |
| Provider notifications are processed once | unique `payment_provider_events.event_key`, checked under the payment row lock |
| QRIS amount equals transaction amount | `charged = server tariff` (CHECK); PAID only when the provider-reported amount equals `payments.amount` |
| Tariff history is never overwritten | tariffs are insert-only; changes become new rows with `effective_from` |
| Ledger and audit are immutable | `AppendOnlyTable` triggers + no UPDATE/DELETE grant for the runtime role |
| Cash balance equals the ledger | `attendant_cash_balances` rows locked `FOR UPDATE` per ledger insert; rebuild command |
| Stale offline tariff is preserved | `charged_tariff_amount` (what really happened), `server_expected_tariff_amount`, `tariff_difference_amount`, anomaly `TARIFF_MISMATCH` |
| Voided PAID QRIS keeps its payment | payment status untouched; refund = `payment_adjustments` row (`MANUAL_REFUND`) |

### System settings (SystemConfiguration)

Policy values are data, not constants ([ADR-0008](../decisions/0008-offline-operation-policy.md)).
They are introduced with their first consumer (Phase 3).

| Key | Initial dev/default value | Used by |
|---|---|---|
| `offline_transaction_warning_hours` | 24 | Flag offline transactions older than this (they are still accepted) |
| `max_open_shift_hours` | 16 | Flag shifts open longer than this; enables supervisor force close |
| `offline_config_max_age_hours` | 72 | Max age of cached bootstrap data for offline shift start |
| `qris_expiry_minutes` | 15 | Lifetime of a dynamic QR (sent to the provider as `custom_expiry`) |
| `qris_status_check_seconds` | 10 | Minimum interval between provider status calls while the app polls |
| `movement_max_speed_kmh` | 60 | Impossible movement: faster jumps between two transactions are flagged |
| `movement_min_distance_m` | 1000 | Impossible movement: shorter jumps are ignored (GPS jitter) |
| `monthly_revenue_target` | 0 | Executive dashboard target in rupiah (0 = none) |
